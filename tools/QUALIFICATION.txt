Package qualification tools

Rscript tools/qualify.R [new-output-directory]

Creates a frozen source snapshot and isolated package library, builds the source
archive INCLUDING its executable vignettes, installs it, exercises the installed
R help/vignette/pipe/table interface and downstream C++ header/callable API,
runs acceptance tests, native sanitizer checks and a full
R CMD check --as-cran including the manual. Logs, test result objects, the source
archive and a manifest survive failure. No user library is modified. Dependencies
must already be installed; the runner does not download or install them.
Building the vignettes needs the declared knitr/rmarkdown development packages
and a Pandoc version supported by rmarkdown (at least 2.8 in the current
qualification). Installed Markdown NEWS checks on older R also need the
declared commonmark and xml2 Suggests dependencies. The installed-interface phase fails
when the built guides were omitted.

Options (environment variables):
  GOF_SLOW_TESTS=true          Include seeded calibration tests (default false).
  GOF_NATIVE_COMPILERS=g++,clang++
                              Native compiler paths, separated by commas.
  GOF_CXX_STD=CXX23            Select an integration standard in the COPY ONLY.
                              CXX14, CXX17, CXX20 and CXX23 are accepted.
                              DESCRIPTION and Makevars are updated together.
  GOF_RUN_NATIVE=false         Omit native checks; recorded as not requested.
  GOF_RUN_CHECK=false          Omit R CMD check; recorded as not requested.
  GOF_CLMM_WORKERS=4           Worker count for the opt-in CLMM cohort.
  GOF_CLMM_CALIBRATION_REPORT  Output RDS path for the CLMM cohort and its
                              resumable per-attempt directory (path + .d).

Rscript tools/clmm-calibration.R OUTPUT [full|slow|pilot] [N] [workers]

Runs a frozen CLMM protocol against the selected installed package. The full
study defaults to 1,000 attempts in each of 29 cells (19 core null cells,
five link cells and five alternatives), with R = 199 and fixed covariate
ordering. Nested cells have three children per top-level cluster and nc rows
per child. Pilot and slow-test modes use separate seed banks. The opt-in test
uses four cells with 500 attempts each. Attempts are atomically retained and
execution resumes only under an identical protocol and installed-R hash set.
Never overwrite a prior cohort after changing the estimator or protocol.

summary.csv retains conditional rejection rates, exact pointwise binomial
intervals, refusal counts, covariance-z strata and a descriptive uniformity
distance; pvalue-histograms.csv retains the binned p-values. Every failed fit
stays in refusal accounting. The declared primary rule at m >= 50 is 5% size
in [0.03,0.075] with refusal below 5%. A failed rule remains a failed gate.
Neither a successful software check nor conditional size among accepted fits
certifies the procedure for all attempted datasets or arbitrary designs.

Rscript tools/export-clmm-evidence.R AUDIT_DIRECTORY DESTINATION

After confirmation completes, audits all retained attempt records, planned
keys/seeds, status counts, rates, exact intervals, uniformity distances and
histograms before atomically creating the compact installed evidence. JSON
provenance export requires jsonlite in the development library. Failed project
criteria are exported as failures; the tool does not change thresholds or
select only successful cells. The original source snapshot and execution
receipts remain outside the checkout.

Rscript tools/check-clmm-input.R [new-output-directory]

Reproduces the asymmetric-link input-fitting check on two deterministic
fixtures. Select an isolated gof >= 1.4.0 library first. The tool compares
the declared and opposite Gumbel likelihoods by independent scalar
integration, verifies gof's declared-link values and the matrix backend's
Laplace value, and retains all warnings, package versions and CSV results.
This is an implementation audit, not a calibration study. It does not patch
ordinal, change the confirmation protocol or alter any installed package.

Native C++14/17/20/23 checks require Bash, a suitable C++ compiler, system Armadillo development
files and sanitizer runtimes. The R package itself uses RcppArmadillo. Run the
native script independently with:
  CXX=clang++ bash tools/check-native.sh c++23

A full manual check also needs LaTeX, qpdf, HTML Tidy and the V8 R package. Incoming
checks need network access to CRAN. Standard _R_CHECK_* environment settings are
respected and recorded; the runner does not quietly disable dependency or
documentation checks. Check notes are retained; errors and warnings fail the
qualification. Tests and manifests identify phases which were not requested.

Rscript tools/measure-coverage.R [new-output-directory]

Uses covr on a separate source snapshot (tests, examples and installed C++ client).
It saves expression/
line counts, per-file and per-R-function summaries and uncovered locations. Set
GOF_SLOW_TESTS=true to include calibration paths. Install covr in a development
library first. This command writes no external coverage service. Native helpers
which are not used by R need the independent C++ harness as well.

Rscript tools/check-documentation.R [new-output-directory]

Checks documentation in a COPY, leaving the repository untouched. Install
roxygen2, rmarkdown, pkgdown and the package's development dependencies in an
isolated development library first. The command regenerates all roxygen help
and NAMESPACE, checks those files and the recorded generator version,
renders README.Rmd against the copied source and checks README.md freshness,
then builds a complete pkgdown site locally. It writes source snapshots,
phase logs, captured input hashes, a manifest and the HTML site under the requested output directory.
No website is deployed and no user library is replaced. A fresh R session
prevents an old loaded namespace from concealing source changes.
The final source-unchanged phase rejects input changes made during the run;
freshness comparisons use captured inputs rather than a moving working tree.
The website phase fails on Pandoc rendering warnings, including mathematics
which would otherwise appear as unconverted TeX. A canonical website URL is
optional for a local preview and must not be invented before hosting is chosen.

README text is compared after normalizing line endings and trailing spaces.
Generated README figure filenames and nonempty files are checked; image bytes
are not compared across graphics devices or operating systems. Set
GOF_DOCS_BUILD_SITE=false to omit the local site explicitly; the manifest
records that omission. The recorded generator version (Config/roxygen2/version,
or the legacy RoxygenNote field) must match the version used to regenerate the
committed documentation. Install that version for an
exact replay, or update all generated documentation together when upgrading.

The GitHub Actions workflow is a runnable portability matrix, not evidence that
those remote jobs have executed. It covers R release on Linux/macOS/Windows,
Linux R devel/oldrel-1/the R4.1 minimum, C++23 package integration on each OS,
generated-documentation/README/local-site checks, one seeded calibration
job, and GCC/Clang native C++14/17/20/23 sanitizer jobs. It is based on the maintained r-lib
example and uses pinned action commits, read-only repository permissions and
no publication or notification steps. Maintainer-triggered remote runs are still
required before claiming macOS/Windows or additional-R-version validation.

Primary workflow reference:
  https://github.com/r-lib/actions/blob/v2/examples/check-standard.yaml

The R-package baseline is C++17. Native utilities are additionally tested under
C++14. R4.6 ignores a C++14 request and uses its newer default; the installed
client tool reports actual __cplusplus so this fallback is not mislabeled as
a genuine C++14 build. Explicit C++23 clients must compile above C++20.

python3 tools/check-static.py --source ../qualification/source \
  --install-log ../qualification/logs/install.log --output ../native-static-new

Requires Python 3, matching clang-tidy/clang-check/clang-format tools (locally
qualified with LLVM 19), and a completed Clang installation log containing
expanded commands for every translation unit. Use the raw source snapshot;
the built R archive excludes the development .clang-format/.clang-tidy files.
The runner rebases actual R-backed compiler commands into compile_commands.json,
checks owned formatting and header isolation, and runs clang-tidy and the
Clang Static Analyzer. Commands, diagnostics, multi-file analyzer reports,
suggested fixes and source hashes are retained. Source is never rewritten.
Generated Rcpp bindings remain in the database but are not manually analyzed
or formatted. The CI workflow has a matching static-analysis job.

Analyzer and portability diagnostics fail the gate, including clang-check
findings emitted with a zero process exit status. The opt-in constructor
UninitializedObject check remains advisory because it flags unused auxiliary
storage in Armadillo templates. Actual uninitialized-read diagnostics still
fail. Other enabled tidy advisories remain visible and require review;
successful exit alone does not mean zero findings. Numerical/RNG replay,
sanitizers and scientific calibration are separate validation activities.

GOF_CHECK_LEAKS=1 enables LeakSanitizer in the native harness. It defaults to 0
for traced local environments; the CI native jobs explicitly enable it. Local
disabled leak checks do not establish absence of memory leaks.
